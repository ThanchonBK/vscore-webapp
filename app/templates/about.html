Method, and what these numbers mean

The seven scores

Each normal mode is projected against seven reference motions. All seven come from one displacement vector d and the equilibrium geometry.

s[Tx], s[Ty], s[Tz] mean of the per-atom unit displacements, per axis. Range [−1, 1]; ±1 = every atom moving together along that axis.
s[Rx], s[Ry], s[Rz] for each off-axis atom, r⊥ and d normalised separately, crossed, and the axis component taken — keeping the sin φ factor, so motion that isn't purely tangential is down-weighted. Range [−1, 1].
s[VS] weighted mean of per-bond directional cosines, Σ w|Δb|²|cos| / Σ w|Δb|². Range [0, 1]; 1 = pure bond-length change, 0 = pure angle change. Weight w is the reduced mass μAB under the active mu variant.

The label

Every mode is labelled from s[VS] alone, on a single cut point: S stretching (≥ τSB), B bending (below it). This is the binary scheme the paper standardised on; every mode gets one or the other, so SB (mixed) no longer appears. It is asked of every mode because it is answerable for every mode — a stretch/bend split needs nothing but the mode's own V-score.

T/R candidates

Whether a mode is a rigid-body translation or rotation is a separate question, and one that depends on the mode set rather than on any single mode. Six external slots (three translations, three rotations — two if the molecule is linear) are assigned across the whole pool by a one-to-one Hungarian assignment maximising Σ|score|. Whichever mode wins a slot gets that slot's bare name — a plain Hungarian pick, no purity gate — matching the reference manuscript's Table 4, which never stars a label or defines a purity threshold.

That assignment is one-to-one over whatever pool it is given, so it always names six modes — even when the set contains no rigid-body motion at all. An EMIT basis is exactly that case: nothing in it is a translation or a rotation, yet six modes are still the closest match to those slots. So the picks are not written into the table. They are listed separately as T/R candidates, each with its related score — the mode's own score in that slot's column, which says how much it resembles that motion, not how likely it is to be one. On benzene's EMIT set the three translations come out at 1.000 while the "rotations" sit at 0.22–0.38, and that gap is the whole point of showing the number.

Tick "treat these as real T/R modes" to fold them into the table, where they read Tx exactly as the classifier labelled them. Leave it unticked and every mode stays a stretch or a bend. The choice is yours to make per result, it changes nothing that was computed, and the CSV you download records which view it came from.

On a 3N−6 upload the ideal T/R references are constructed and win all six slots — across the 26 reference molecules, none of their 463 real vibrations ever took one — so there are no candidates to decide about. The reference rows are shown (toggle "reference modes") as a sanity check on the alignment, not as results; they keep their T/R labels, being rigid-body motions by construction.

The highlighted cell

The highlight follows the label, not the biggest number — it marks the score the verdict was actually read from. With every mode labelled S or B, that is s[VS]. Accept a T/R candidate and its row moves to its slot's column instead. The six T/R numbers stay visible on every row either way: they are diagnostics, and marking one on a mode the algorithm never assigned would assert external character it does not have.

The separate dominant score reported in the CSV is the largest absolute value of the seven, not the largest raw value. s[VS] alone cannot be negative, so a raw comparison would favour it structurally — it would win 64% of modes rather than 57%, and would pick +0.087 over −0.283. A mode translating along −x is exactly as translational as one along +x.

Connectivity is never guessed

Bonds come from your input deck or your .vsc, and every result page lists the bonds it used. There is no distance cutoff anywhere in this app. An empty bond list makes s[VS] exactly 0.000 for every mode and labels the whole table B — a silent, plausible, wrong answer — so missing connectivity is an error, not a default.

Frame

The molecule and its displacement vectors are rotated together into the principal axes of inertia before scoring, so x, y, z in the table mean the principal axes. s[VS] is rotation-invariant; the T and R scores are not, and are only meaningful in this frame. The 3D viewer shows that same frame.

For a symmetric top, a spherical top or a linear molecule the principal axes are not unique — the perpendicular axes can turn freely — so by default the frame is fixed by the symmetry rule: z on the Cn axis and y through an atom of the smallest set of symmetry-equivalent off-axis atoms (spherical tops: three perpendicular C2 axes; linear molecules: the turn about the axis from the modes' in-plane displacement), with a tie-break on the modes' translation scores and a naming convention for signs. The same input then gives the same T/R scores in any orientation. The submitted version's frame (inertia eigenvectors, which leave those axes arbitrary) can still be chosen under Settings, along with keeping the input frame where the rule allows it.

Scope

This app runs the scoring algorithm and nothing else. Calibration of τTR/τS/τB, library ingest, PED merging and figure generation all live in the reference implementation. The thresholds shown on each result are read from its published calibration and are not editable here — they are cut points on an s[VS] distribution, so pairing them with a different V-score definition would silently mislabel stretches and bends.

Verification

The scoring core is a verbatim copy of the reference implementation (scoring.py, classifier.py, utils.py, thresholds.json), with only import paths adjusted. All 24 reference molecules with both a log and an input deck reproduce their published results with a worst-case deviation of 0.00e+00 and no label changes, and all 69 log/deck pairs round-trip through a downloaded .vsc with identical scores and labels.
